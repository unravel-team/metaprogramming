* Standalone language scaffolds

Each language folder is complete starting point for one service and library. Copy
one folder into its own Git repository before customization. Scaffolds do not
coordinate through root Makefile or hidden bootstrap scripts.

Choose one of =clojure/=, =golang/=, =python/=, or =typescript/=. Then replace
placeholder package/library and Fly app identities before releasing or deploying.
Read copied folder's =README.md= for language-specific details.

* Setup

Install host runtime and package manager first; scaffold setup never installs host
tools. Docker Compose supports local PostgreSQL, =tagref= supports reference
checking, and Fly CLI is needed only for Fly deployment.

| Folder       | Host prerequisites                                  | Project setup installed by =make init=             |
|--------------+-----------------------------------------------------+----------------------------------------------------|
| =python/=    | Python 3.12+, =uv=, =tagref=                        | locked Python dependencies                         |
| =typescript/=| Node.js 22+, Corepack, =tagref=                     | locked pnpm dependencies                           |
| =golang/=    | Go 1.26+, =tagref=                                  | modules; pinned local Air, Goose, audit, lint tools|
| =clojure/=   | JDK 21+, Clojure CLI, =tagref=                      | pinned Clojure aliases                             |

In copied scaffold:

#+begin_src sh
make doctor
make init
make check test
make build
#+end_src

=make init= is only normal setup entry point. It copies =.env.example= to =.env=
only when absent, then installs or prefetches checked-in dependencies as needed.
Normal =check=, =test=, =build=, =dev=, and migration targets never invoke setup
installers or deliberately update manifests/locks. Native dependency resolvers may
still fetch missing cached dependencies; Clojure has no frozen/offline guarantee. Use =make upgrade-deps= for deliberate dependency
maintenance and review resulting metadata and lock changes.

* Common workflow

| Target                 | Meaning |
|------------------------+---------|
| =help= / =doctor=      | List targets / diagnose host and project tools. |
| =check=                | Dependency consistency plus format, static, and reference checks. |
| =format=               | Apply language formatter. |
| =test=                 | Default unit and property suites. |
| =test-unit= / =test-property= | Run one default test category. |
| =test-integration= / =test-llm= | Run explicit optional external category. |
| =test-all=             | Run every test category. |
| =test-coverage=        | Write coverage separately from normal tests. |
| =build=                | Wait for =check= and default =test= before artifact creation; gates may run concurrently. |
| =audit-deps=           | Networked advisory scan, separate from offline checks. |
| =ci=                   | Run =check=, default =test=, and =audit-deps=. |
| =clean= / =clean-cache=| Remove generated artifacts / language-specific caches. |

Property suites use Hypothesis (Python), fast-check (TypeScript), Rapid (Go), or
test.check (Clojure). Generated failures shrink to small counterexamples. Optional
integration and LLM targets invoke their real runners; their documented empty-suite
policy does not turn a runner failure into success.

Coverage has no arbitrary percentage gate. Reports show unexecuted production code
where tool supports it, while external integration/LLM paths remain uncovered until
those systems exist. TypeScript V8 coverage does not render async Next server
components in its Node test environment; use dedicated integration coverage for
those paths.

* Dependency, database, and infrastructure policy

After =make init=, normal dependency checks do not mutate manifests or locks:

| Folder       | =check-deps= guarantee | =audit-deps= |
|--------------+------------------------+--------------|
| =python/=    | =uv lock --check= validates =uv.lock=. | =pip-audit=; network required. |
| =typescript/=| frozen pnpm lock validation without install. | pnpm audit; network required, fails at low severity. |
| =golang/=    | =go mod verify= and =go mod tidy -diff=. | project-local =govulncheck=; network required. |
| =clojure/=   | =-Srepro= resolves base plus =:test=, =:run=, and =:migratus= classpaths; not frozen/offline. | clj-watson scans base plus =:migratus=; network and =CLJ_WATSON_NVD_API_KEY= required. |

Each scaffold supplies PostgreSQL Compose template and migration target. Migration
tools remain language-native: Alembic (Python), dbmate (TypeScript), Goose (Go),
and Migratus (Clojure). After Python =make init=, all Alembic migration targets
load =.env= through UV and an exported =DATABASE_URL= wins. =make migrate-create=
creates a migration; Python's Alembic autogeneration also inspects the configured
database. =make migrate= contacts that database. =make migrate-status= reports
migration state; =make migrate-rollback= reverses the latest applied migration. Clojure Migratus uses exported =DATABASE_URL=
first, otherwise a plain unquoted value from =.env= read as data without shell
evaluation. Treat both as explicit operations.

=make infra-up= starts local services; =make infra-down= stops them. =make
infra-down-clean= warns about irreversible local data loss and removes volumes only
after exact =yes=. EOF, refusal, and every other response preserve volumes.

* Development, Fly, and artifacts

| Folder       | Development service | Build artifact |
|--------------+---------------------+----------------|
| =python/=    | FastAPI reload, port 8000 | wheel and source distribution |
| =typescript/=| Next development server, port 3000 | Next app plus staged =dist/= library package |
| =golang/=    | project-local Air, port 8080 | =bin/golang= Fly application binary |
| =clojure/=   | JVM HTTP server, port 8080 | library JAR in =target/= |

All deployed containers bind =0.0.0.0:8080= and expose =GET /health=. =make
deploy= builds locally, rejects placeholder Fly app identity, then calls Fly. No
normal verification, release, or publication target deploys automatically.

* Version, release, and publication

=make version= prints semantic version. =make major=, =make minor=, and =make
patch= change version metadata only, using normal semver reset rules. They never
commit, tag, push, or change branches. Go v2+ bumps additionally require matching
=/vN= module import path.

=make release= validates and builds clean, committed, standalone repository, then
creates local annotated =vVERSION= tag. It refuses nested template folder, so a
copied scaffold cannot tag containing repository by mistake.

Publishing is explicit and credential-guarded:

| Folder       | Target | Publication behavior |
|--------------+--------+----------------------|
| =python/=    | =deploy-pypi= | Publish current wheel and source distribution with =UV_PUBLISH_TOKEN=. |
| =typescript/=| =deploy-npm= | Publish staged =dist/= library package with =NPM_TOKEN= through restrictive temporary npm config. |
| =golang/=    | =deploy-go= | Push current release tag to =origin= for module discovery; no central upload. |
| =clojure/=   | =deploy-clojars= | Publish current JAR/POM with Clojars credentials. |

Every publication target requires unique identity, clean standalone exact-HEAD
annotated release tag, and its credentials. None run as part of =release= or =ci=.

* Cache behavior

=make clean= removes generated artifacts. Use =make clean-cache= only when
troubleshooting language caches:

- Python uses =.cache/uv= and removes only that UV cache plus project pytest/Ruff caches.
- TypeScript uses =.cache/pnpm/store= and removes that store plus project Next/tool caches, not installed dependencies.
- Go uses =GOCACHE=.cache/go-build= and clears only that build/test cache, preserving shared caches and downloaded modules.
- Clojure removes project CLI and linter caches, preserving global Maven cache.

All =clean-cache= targets reject symlinked deletion paths and parent directories.
Run =make init= to populate the project-local caches when needed.
